# Implementation review through the code lenses and state-machine skill

Scope: the Go migration branch plus the preserved nomenclature overlay. This is a source review by the implementation agent, supported by the listed tests; it is not an independent advisor sign-off or production proof. The Codex–Opus agreement remains the design authority. Source references are relative to this repository.

The state model is documented in `go-protocol.md`. In particular, a job being done and its artifacts being available are separate facts. Wrong-kind polling cannot mutate a job. Pending age never expires unstarted work. Retry changes authority tokens while retaining public job identity. A cancelled worker reaps its process group before releasing the attempt for bounded retry.

The final packaged rollback drill stopped the candidate API and worker, verified the worker was reaped, then started a separate compatible quiesced API on the same local port. Existing Go and legacy IDs remained done, their artifact hashes were unchanged, and new admission returned 503. This establishes isolated process replacement/read continuity, not production ingress or backup restore.

Review corrections made while implementing included retaining consumer snake_case aliases and harmless metadata, mapping flat conformer options, avoiding four-decimal identity collisions, preserving valid blank MOL titles, fixing V2000 fixed-width counts, reading native xTB's actual atomic-unit dipole field, rejecting unsupported radii, keeping scientific failures distinct from infrastructure retry, filtering claims by adapter compatibility, and retiring the unsafe legacy push-to-main deployment path.

Remaining proof boundaries: local native checks use linux/amd64 emulation on an ARM Mac; the 398-case complete naming benchmark used local RDKit/Openclatura with Java, with a native Linux OPSIN smoke test as well. One naming case is an explicit OPSIN mismatch, not marked verified. The real isolated consumer integration passes checks/build, 52 focused tests and seven actual HTTP cases, including pairing with final server `e2abc7b`. It is not deployed. Remote CI, live host identity/topology, production backup restore, actual ingress cutover and provider-specific capacity remain unproven. No provider or billing change was made.

## Consumer and small-host follow-through

The consumer authority lens reproduced incorrect reuse after conformer seed/input changes; full inputs, effective options and adapter compatibility now own cache identity. Shared payload construction keeps browser proxy and server-side defaults aligned. Existing cancellation still ends observation without rewriting durable execution; actual handler-to-Go tests preserve this boundary.

The optional small-host ownership/bounds review split claim eligibility into one long and one short worker without a new queue. Real PostgreSQL tests prove default/all-kind behavior, filtered claiming and readiness coverage including stale/wrong-version workers. A fresh naming request and conformer completed while caffeine Psi4 remained running; the final 4-GiB workload, interruption recovery and actual memory/disk receipts are linked in `vps1-capacity.md`. The initial uncontrolled test-helper connection burst OOMed PostgreSQL; that failure is preserved and the bounded test configuration is explicit.

The failure/state lens found that result-read saturation incorrectly reported artifact unavailability. It now returns 503 `busy` and `Retry-After: 1`; a deterministic real-PostgreSQL test fills both read slots, verifies job/artifact GET behavior and confirms durable `done`/available state remains intact. Releasing capacity restores reads. This changes transient error classification, not scientific bytes or completion authority. Final server `e2abc7b` and unchanged consumer application `7c8254ab` pass the paired integration through Caddy.
